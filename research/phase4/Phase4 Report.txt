INCREMENTAL CONTRACT
frame: epoch, identity, trade_date, sequence, status=DURABLE_COMMITTED, as_of, events, payload_sha256.
Hash = SHA256(UTF-8 JSON.stringify(frame without payload_sha256)), retaining field/array order. This is an offline normalized envelope, NOT the C2 wire format. A hash alone does not prove authenticity or persistence.
event kinds: ADMIT, EXIT, QUOTE, CANDLE, TECHNICAL, ATR, TRANSPORT.
ADMIT requires injected frozen backfill with symbol/date/identity/complete and data.current/history/pool/quote. Complete=true is an isolated upstream assertion, not independently authenticated natural coverage. Same-as-of source quality must be independently wired before formal use.
CANDLE identity = symbol plus numeric timestamp; same-minute and older-minute revisions replace that key. Duplicate identical rows do not trigger Discovery. Current bars are ordered and duplicate timestamps (including equivalent timezone representations) are refused. A forming/future bar is refused.
Quote updates cause Strategy3 re-evaluation but do not rerun candle-only anomaly formulas. Transport-only updates do not rerun anomaly Discovery. Pending deep-analysis states still run/expire with the evaluation clock. All original quote serial/event ordering is an upstream prerequisite; this adapter must not be fed unvalidated raw quotes.
EXIT removes current result membership. Re-entry backfills a fresh frozen input, preserving event/outbox dedup history. The original universe is neither expanded nor reduced by this adapter.
GAP, sequence gaps, epoch/date change, integrity conflict or unknown older replay stops without advancing checkpoint. Last 64 exact frame hashes support replay dedup; older unknown replay requires recovery.
Recovery here means reopening the last atomic offline state or requiring a new independently verified full baseline. It does not implement or bypass C2 recovery.

CHECKPOINT / OUTBOX / CRASH
Result maps, pending frozen trigger state, dry outbox, sequence and frame digest commit in one temp-file + fsync + rename transaction. Exclusive per-directory offline-owner.lock prevents overlapping transactions; state is independently reloaded after ownership acquisition. A crashed owner lock is not automatically stolen. Before-rename crash retains previous state; after-rename replay deduplicates. This is an offline state simulator, NOT production durable-storage certification; directory fsync / Windows power-loss guarantees have not been asserted.
Only confirmed original gate events enter DRY_RUN_PENDING outbox. No sender exists. Ordered simulated acknowledgements are persisted and idempotent. Notification exactly-once across a real external send/ACK crash is NOT established; downstream idempotency/reconciliation remains required.
Original trigger/level evidence is frozen in existing gate state. Later same-key revisions are not used to rewrite an already frozen trigger; revision-after-event is recorded. No retroactive past notification/retraction policy is introduced.

BOUNDARIES / LIMITS
2500 symbols; 271 current bars/symbol; 5420 historical bars/symbol; 200000 total bars; 5000 events/frame; 4MiB frame; 64MiB serialized state; 20000 dry outbox entries; 64 replay hashes. Exceeding a bound aborts the transaction; no truncated success.
These are offline envelope limits, not a change to any production Gate or Universe. They do NOT prove capacity for 2500 symbols times 20 full historical days. The test inputs are already allocated JS objects; upstream bounded streaming input is not supplied here.
Current state is cloned and serialized as a whole on each commit. Thus formula evaluation is incremental, but state persistence I/O is NOT incremental. This limitation is explicit and blocks any production performance claim.

REMAINING BLOCKERS
1. Authenticated Phase1 C2 + Phase2 durable commit/parent completeness + Phase3 membership mapping not formally bound to this normalized envelope.
2. Candle completion/maturity events: a forming saved bar can become complete through passage of time without new WS content. This package requires upstream completed-bar delivery and does not create that clock-driven feed. Changed-only wiring without it would lose evaluation opportunities.
3. Real same-as-of full source reader validation (including95/90, source freshness, quote ordering, native source/units, field hydration) not wired. Existing result maps must not be treated as a live complete scan until these global/time dependencies are resolved.
4. Full-history baseline changes/revisions require explicit invalidation; history treated as frozen per provided snapshot. No silently guessed warm-up policy.
5. Old-minute revisions recompute current eligible latest anomaly and current Strategy3 result, but do not replay every historical affected signal for new notifications. Historical retraction/re-notification remains undefined; original triggers remain frozen.
6. Full wrapper/verifier, three surfaces, natural receipts, actual delivery and external send/ACK idempotency are outside this offline implementation.
7. State I/O is still whole-state; optimized2000-symbol/max-history resource acceptance pending.

There is no formal switch to roll back because no formal path was connected.
No Collector/Writer/Strategy3/Telegram/runtime/DB/schema/task/subscription was modified. No natural Shadow, no real notification, no order. Implementation can be reviewed independently; formal Consumer GO remains NO_GO.
